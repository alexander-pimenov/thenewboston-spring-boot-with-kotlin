Да, есть несколько аннотаций для изоляции тестов:

## **1. `@TestInstance(Lifecycle.PER_METHOD)` (по умолчанию)**
```java
import org.junit.jupiter.api.TestInstance;

@TestInstance(TestInstance.Lifecycle.PER_METHOD) // Каждый тест в своем экземпляре класса
class UserControllerTest {
    // По умолчанию JUnit 5 создает новый экземпляр для каждого теста
    // Но поля @MockBean и @Autowired могут сохранять состояние!
}
```

**Проблема**: Даже с `PER_METHOD`, Spring-бины (`@MockBean`, `@Autowired`) переиспользуются между тестами в рамках одного тестового класса!

## **2. `@DirtiesContext` - самое надежное решение**
```java
import org.springframework.test.annotation.DirtiesContext;

@WebMvcTest(UserController.class)
@DirtiesContext(classMode = DirtiesContext.ClassMode.AFTER_EACH_TEST_METHOD) // ← Ключевая аннотация
class UserControllerTest {
    // После каждого теста Spring Context будет полностью пересоздан
    // Все бины будут свежими, никакого общего состояния
}
```

### **Варианты `@DirtiesContext`:**
```java
@DirtiesContext(classMode = DirtiesContext.ClassMode.AFTER_EACH_TEST_METHOD) // После каждого метода
@DirtiesContext(classMode = DirtiesContext.ClassMode.AFTER_CLASS) // После всего класса
@DirtiesContext(classMode = DirtiesContext.ClassMode.BEFORE_EACH_TEST_METHOD) // Перед каждым методом
@DirtiesContext(methodMode = DirtiesContext.MethodMode.AFTER_METHOD) // Только для метода
```

## **3. Использование `@Nested` классов**
```java
@WebMvcTest(UserController.class)
class UserControllerTest {
    
    // Каждый @Nested класс получает свой собственный Spring Context!
    
    @Nested
    @DisplayName("POST /api/v1/users tests")
    class CreateUserTests {
        @Test
        void test1() { /* Изолированный контекст */ }
    }
    
    @Nested
    @DisplayName("GET /api/v1/users tests")  
    @DirtiesContext // Можно комбинировать
    class GetUserTests {
        @Test
        void test2() { /* Другой изолированный контекст */ }
    }
}
```

## **4. `@TestExecutionListeners` с `DirtiesContextTestExecutionListener`**
```java
import org.springframework.test.context.TestExecutionListeners;
import org.springframework.test.context.support.DirtiesContextTestExecutionListener;

@WebMvcTest(UserController.class)
@TestExecutionListeners(
    listeners = DirtiesContextTestExecutionListener.class,
    mergeMode = TestExecutionListeners.MergeMode.MERGE_WITH_DEFAULTS
)
class UserControllerTest {
    // Более тонкий контроль над слушателями тестов
}
```

## **5. Полное решение для вашего случая:**

```java
@WebMvcTest(UserController.class)
@Import({UserMapper.class, ValidationConfig.class, TestSecurityConfig.class, GlobalExceptionHandler.class})
@DirtiesContext(classMode = DirtiesContext.ClassMode.AFTER_EACH_TEST_METHOD) // ← ГЛАВНОЕ
@TestInstance(TestInstance.Lifecycle.PER_METHOD)
class UserControllerTest {

    @Autowired
    private MockMvc mockMvc;

    @MockBean
    private UserService userService; // Новый мок для каждого теста

    @Autowired
    private ObjectMapper objectMapper;

    // Не нужен @BeforeEach для reset() - контекст пересоздается!

    @Test
    @DisplayName("POST /api/v1/users - создание пользователя")
    void createUser_withValidRequest_returnsCreated() throws Exception {
        // Arrange
        CreateUserRequest request = new CreateUserRequest("test@example.com", "Password123!");
        User user = User.builder()
                .id(1L)
                .email(request.getEmail())
                .status(UserStatus.ACTIVE)
                .build();

        // Мок настраивается ТОЛЬКО для этого теста
        when(userService.createUser(any(CreateUserRequest.class))).thenReturn(user);

        // Act & Assert
        mockMvc.perform(post("/api/v1/users")
                        .contentType(MediaType.APPLICATION_JSON)
                        .content(objectMapper.writeValueAsString(request)))
                .andExpect(status().isCreated());
    }

    @Test
    @DisplayName("GET /api/v1/users - пагинация")
    void getUsers_withPagination_returnsPage() throws Exception {
        // Arrange - свой собственный мок, не зависящий от других тестов
        Page<User> userPage = new PageImpl<>(List.of(
                User.builder().id(1L).email("user1@example.com").build(),
                User.builder().id(2L).email("user2@example.com").build()
        ));

        when(userService.getUsers(0, 10, null)).thenReturn(userPage);

        // Act & Assert
        mockMvc.perform(get("/api/v1/users")
                        .param("page", "0")
                        .param("size", "10"))
                .andExpect(status().isOk());
    }
}
```

## **6. Альтернатива: `@MockitoBean` (Spring Boot 3.1+)**

```java
import org.springframework.boot.test.mock.mockito.MockitoBean;

@WebMvcTest(UserController.class)
class UserControllerTest {
    
    @MockitoBean // Автоматически сбрасывается после каждого теста

}
```

## **7. Компромиссное решение - изоляция только моков:**

Если не хотите пересоздавать весь контекст (медленно), можно изолировать только моки:

```java
@WebMvcTest(UserController.class)
class UserControllerTest {

    @Autowired
    private MockMvc mockMvc;

    @MockBean(reset = MockReset.AFTER) // Сброс после каждого теста
    private UserService userService;
    
    @MockBean(reset = MockReset.AFTER)
    private PasswordEncoder passwordEncoder;

    @Autowired
    private ObjectMapper objectMapper;

    @Test
    void test1() {
        // userService будет сброшен после этого теста
    }
    
    @Test  
    void test2() {
        // userService чистый, не зависит от test1
    }
}
```

## **8. Самый быстрый вариант - правильная настройка моков:**

```java
@WebMvcTest(UserController.class)
class UserControllerTest {

    @Autowired private MockMvc mockMvc;
    @MockBean private UserService userService;
    @Autowired private ObjectMapper objectMapper;

    @BeforeEach
    void setUp() {
        // Явно настраиваем ВСЕ возможные вызовы
        Mockito.reset(userService);
        
        // Дефолтные значения для всех методов
        when(userService.getUsers(anyInt(), anyInt(), any()))
            .thenReturn(new PageImpl<>(Collections.emptyList()));
        
        when(userService.getUserById(anyLong()))
            .thenThrow(new UserNotFoundException("Not found"));
        
        // и т.д. для всех методов
    }

    @Test
    void specificTest() {
        // Переопределяем только нужный мок
        when(userService.getUserById(1L))
            .thenReturn(User.builder().id(1L).build());
        
        // остальные методы используют дефолтные настройки из setUp
    }
}
```

## **Рекомендации:**

1. **Для надежности**: `@DirtiesContext(classMode = AFTER_EACH_TEST_METHOD)`
2. **Для скорости**: Правильный `@BeforeEach` с полной настройкой моков
3. **Для организации**: `@Nested` классы + `@DirtiesContext` на каждом
4. **Для Spring Boot 3.1+**: `@MockitoBean` вместо `@MockBean`

## **Пример с `@Nested` + `@DirtiesContext`:**

```java
    @MockBean protected UserService userService;
    @Autowired protected ObjectMapper objectMapper;

    @DirtiesContext
    class CreateUserTests {
        @Test
        void test1() {
            // Изолированный контекст
        }
    }
    
    @Nested  
    @DirtiesContext
    class GetUserTests {
        @Test
        void test2() {
            // Другой изолированный контекст
        }
    }
}
```

**Вывод**: Используйте `@DirtiesContext(classMode = DirtiesContext.ClassMode.AFTER_EACH_TEST_METHOD)` - это решит все проблемы с пересечением данных между тестами, но немного замедлит выполнение.
